- Protótipo: no CSS do toque, `@media (orientation: portrait){#rot{display:block}}` vinha ANTES de `#rot{display:none}` e era anulado (aviso nunca aparecia). No porte (`src/input/toque.css`) a ordem foi invertida de propósito; único desvio visual da 1a. **How to apply:** se o dono estranhar o aviso em retrato, é isso; reverter = mover a media query de volta para cima.
- O CSS do toque é content-box com borda de 2px: a caixa medida de joystick/botões = tamanho calculado + 4px; o knob fica ~2px fora do centro em repouso (fiel ao protótipo). Testes e2e medem com essa folga — não "consertar" sem decidir mudar o visual.
- Canvas real é 1920x1080 (RS=2, `render/tela.ts`), desenho em coordenadas lógicas 960x540 via `usarEspacoLogico`. Mudar width/height do canvas reinicia o contexto (suavização é configurada depois).
- e2e importa módulos do src direto no navegador com `import(/* @vite-ignore */ '/src/x.ts' as string)` (só no dev server); o `as string` evita erro do tsc. Hook `window.__inno.entrada` existe só em `import.meta.env.DEV`.
- Ferramenta Bash: heredoc com apóstrofo em texto PT (ex.: "protótipo's") quebra o parse; usar Write para criar arquivos com texto. `python3` no Windows trava (stub) — usar node.
- Toque simulado no e2e: CDP `Input.dispatchTouchEvent` (projeto "celular" tem hasTouch); viewport paisagem via `page.setViewportSize` antes do `goto`.
- Fidelidade visual: `tests/e2e/fidelidade-prototipo.spec.ts` roda o protótipo original (file://, globais acessíveis por nome em evaluate: game, setKey, renderWorld, drawPose, CHARS, canvas, ctx) numa página, extrai a LeituraLuta + efeitos e compara o PNG 1920x1080 pixel a pixel com `desenharMundo`. Cada cena declara `exige` (o que o quadro precisa mostrar) porque a 1ª versão passou em quadros vazios (lutadores longe, sem golpe conectar). Mutação de 1 ponto de alfa no código quebra o teste. `SALVAR_QUADROS=<pasta>` grava os PNGs de referência.
- Protótipo: o piscar de invulnerabilidade (`globalAlpha=0.6` antes de `pose(im,1)`) é código morto (pose() sobrescreve o alfa); o render novo não o desenha de propósito.
- C3 não tem `dummy` (alvo do treino); o HUD recebe `alvoTreino` por opção até a Vega acrescentar.
- F1c: o oráculo do protótipo precisa de relógio parado (`window.requestAnimationFrame = () => 0` via addInitScript) e de ticks dados por `UI.update()`; senão o `game` anda entre capturas (a câmera guarda estado entre lutas e dá 7º decimal de diferença que vira pixel). Mantive nomes dos campos das cenas iguais aos do protótipo para o mesmo código de teste (`S`, `U`, `G`, `SET`) rodar nos dois lados. Cenas com CPU: capturar dentro da abertura (a CPU só age em `phase==='fight'`) porque o sorteio é semeado e difere do `Math.random` do protótipo.
- Teste de jogo real é sensível a CPU: com 12 workers estourava tempo. `playwright.config.ts` ficou com `workers: 4`; fluxo longo usa afordâncias (posicionar jogador, CPU fraca) e teclas reais só para golpes.
- Resultado: Enter na tela de resultado = revanche imediata (scene.key trata antes do nav); para "MENU PRINCIPAL" por teclado usar Z.
- Logo (paleta A, 2026-10-20): cores em `PALETA_MARCA` (ui/logo.ts); cenas chamam `marca.desenharLogo/Emblema` para os testes poderem desligar só o logo. `fidelidade-ui.spec.ts` desliga logo, emblema e brasas dos dois lados (protótipo: `window.drawLogo/drawEmblem = noop`, `EMBERS` vazio) em vez de mascarar regiões; o logo é medido em `logo.spec.ts`.
- E1b: `ArteLutador` é por quadro e pode ser nula (`imagemDe(pd)`, `silhuetaDe(pd)`, `retrato(head)`); imagens vêm do `GerenciadorDeArte` (carga sob demanda, poda LRU, `usar()` protege quem está em luta). Retrato = `retrato.png` + `retrato.json` (recorte fracionário) gerados por `ferramentas/gerar-retratos.mjs`; NÃO escrever no `atlas.json` (o teste da Vega exige que o regenerado seja igual ao arquivo). C1 v2 (páginas) e v1 normalizam em `ManifestoC1`; a página do quadro fica num WeakMap por objeto de pose. `?precarga=minima` (DEV) testa a via sob demanda de verdade.
- E4: a UI deriva do elenco/regras injetadas (`Contexto.regras`, `Persistencia.prog`); estados novos (3x3, travado, NOVO!, chefão, desbloqueio) só existem com regras de 9 ids, testadas pela fixture `ui/dev-expansao.ts` (`?expansao=1`, import dinâmico só em DEV, ausente do bundle). `CampanhaArcade.etapas` (de `montarEscada`) no lugar de `order`. Cursor da seleção anda por cima de travados (decisão pendente com o dono). HUD de barras lê campos opcionais (`ExtensaoChefeLeitura`) até a E3.
- Órion/E8 (2026-10-21): CSP vai por plugin `cspSoNoBuild` em `vite.config.ts` (só build) e é validada por `npm run test:e2e:build` (`playwright.build.config.ts`, porta 4173, sem ganchos `__inno`); o e2e normal (dev server) nunca vê a CSP. Aviso "não salvo" = `platform/aviso.ts` + `ui/persistencia.ts` (`salvar()` devolve boolean). Faixa `left:50%`+translateX precisa de `width:max-content` (senão quebra em 2 linhas). e2e longo quebra com HMR quando outro agente edita `src/`: rodar com vite `watch:null,hmr:false` em 5173. Detalhes em `docs/handoff-lyra-orion.md`.
- Pós-E3: render por ficha = `chDaFicha(ch, f.ficha)` (render/lutador.ts); usar `ficha ?` (não `!== null`) porque leituras falsas de teste (e4-ui) não têm o campo. `fase-chefe` tem 3 etapas: efeito visual só em `troca`; danca/retomada sem overlay (não existe). `ler()` sempre traz `spSeg` (false solto): `VAZIO` dos testes (teclas.test, entrada.spec) precisa do campo. UI nunca reconstrói `Progresso` (sempre via meta); teste e2e "progresso de uma onda futura" guarda `desconhecidos`.
- F3a (2026-10-21): no Windows/Git Bash `pkill -f` NÃO mata o vite; o servidor "fixo" velho seguiu servindo `main.ts` antigo e causou falhas falsas. Matar com `Stop-Process` (Get-CimInstance Win32_Process por linha de comando) e conferir `curl /src/main.ts` antes da suíte. `ferramentas/gerar-retratos.mjs` lê a PÁGINA do quadro do rosto (C1 v2) e a janela do retrato cresce com alturaRef (BAATAR 243 px). Fidelidade com o protótipo = `?expansao=4` (4 lutadores) + `tests/e2e/_jp-prototipo.ts` (jp antigo por page.route, arquivo em tests/fixtures). Fixture de 9 falsos aposentada: `?expansao=1` = 9 reais liberados. Medir pés no chão por A/B de pixels (render com/sem a imagem do lutador). Harness que força hp do chefão deve parar quando `barras` trocar (barra nova nasce cheia). Detalhes: docs/handoff-lyra-f3a.md.
- F3b (2026-10-21): oráculo de fidelidade com HAYATO/MIN-JI originais = `usarArteDoPrototipo` em `tests/e2e/_jp-prototipo.ts` (rota 404 para arquivo fora da fixture); TODA página que compara com o protótipo precisa dela, inclusive a do teste `desenharPose`. A/B de pixels (com/sem imagem do lutador) tem de zerar `game.shake` e mascarar pixels que mudam entre dois desenhos: em defesa o tremor dava "base" em y=1079 (borda). Prove a medida com controle negativo (deslocar `getPD(...).y` 30 px). Para provar QUAL quadro foi desenhado: comparar recorte de `getPD(chDaFicha(ch, ficha), pose)` com `manifesto.quadros`. Teste longo (50 s) ao lado dos de jogo real causou flake: dividir em ~25 s. `arte-fonte/` fora do git (capturas novas ~190 MB). `python`/`python3` no Windows trava; usar node (e nunca crase dentro de `node -e "..."` no bash). Detalhes: docs/handoff-lyra-f3b.md.
